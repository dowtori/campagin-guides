# 이전 맵 평가와 v6 재설계


## v6.3: 설정 예시를 직접 채우고 준비 여부만 선택

계정과 도구를 준비하는 목적은 정확한 설정을 익히는 것입니다. 프로필을 한 번에 완성시키는 버튼, 실제 연결이 아닌데 URL을 입력받아 연결했다고 표시하는 화면을 교체했습니다. 매 화면의 행동은 하나이며, 누르면 예시의 해당 자리가 채워집니다. 완료된 모습에서 핵심을 확인하고 이해 여부를 스스로 확인합니다. 정답 카드나 순서 맞히기는 없습니다.

이후 선택은 지금 하기 / 이미 완료했습니다 두 가지입니다. 전자는 받은 안내서에서 실제 설정 후 돌아와 완료를 확인하는 흐름이고, 후자는 다음 과정으로 이어집니다. ‘지금 하기’만 눌러서는 진행 기록을 완료 처리하지 않습니다. 안내서 바로가기는 웹페이지와 메일에서 제공합니다. Roblox 게임 안 외부 링크 공유 제한을 확인했고, 사용자 답변에 따라 이 전달 방식을 채택했습니다. 실제 설정 완료는 사용자 확인으로 기록하며 외부 계정을 검증한 것으로 표현하지 않습니다.

실제 내보낸 클라이언트 소스에서 프로필·연결의 점진적 채움, 중간 복귀, 두 완료 경로, 안내 취소·복귀를 검사했습니다. 원본 로고와 게시물 6장은 그대로 사용합니다. 네이티브 화면의 시각·터치 검증은 여전히 Roblox Studio에서 확인해야 합니다.

## v6.2: 기본 업무 우선, 세 곳으로 이어지는 동선

이전 필수 과정에는 고료 조정과 모르는 제작 조건 문의가 끼어 있었습니다. 기본 업무를 처음 끝내기도 전에 예외를 연속으로 처리하게 했고, 크리에이터 정원에서 반대편 우체통으로 간 뒤 다시 처음 매니저에게 돌아와야 했습니다. 빠른 이동 버튼만으로 이 배치의 문제를 해결할 수는 없었습니다.

필수 방문지를 준비 테라스 → 크리에이터 정원 → DM 데스크로 정리하고, 시작점부터 바다 방향으로 한 길에 배치했습니다. 준비 공간 뒤쪽 벽에 20-stud 통로를 냈고, 크리에이터와 우체통을 주 동선 옆으로 옮겼습니다. 가로막는 가구와 안내판은 길에서 벗어나게 놓았습니다. 프로필·시트 설정은 준비 장소에서 바로 이어지며, 발송·일반 회신·마무리는 같은 DM 데스크에서 완료됩니다. 현재 목표를 누르면 그 장소로 이동할 수도 있습니다.

필수 회신은 ‘지원했어요’에 간단히 답하는 사례입니다. 이후 별도로 도착한 브랜드의 최종 선정 안내를 확인한 뒤 정산합니다. 고료 조정과 모르는 조건은 모든 과정이 끝난 뒤 폰에서 선택해서 읽는 부록으로 옮겼습니다. 부록은 자동으로 열리지 않고, 미션·시험·보상을 추가하지 않습니다.

실제 내보낸 소스의 전체 진행·완료·재시작과 부록의 비필수 동작을 어댑터에서 검사했습니다. 실제 모델 좌표로 필수 도착점까지 133 studs, 세 번의 전진 방문, 표본 캐릭터 통로의 장애물 부재를 확인했습니다. 같은 기하를 사용하는 웹 시점도 확인했습니다. Roblox Studio에서 직접 걷기·점프·터치 화면을 검증하지 못한 한계는 남아 있습니다.

## v6.1: 사용 중 드러난 문제를 반영한 수정

v6에서 폰의 `Tool.Activated`를 바로 열기 동작에 연결한 것은 잘못된 입력 설계였습니다. 작업 버튼을 누를 때도 폰이 다시 열릴 수 있었고, 진행 기록만 보여주는 폰은 이동을 돕지 못했습니다. 또한 원본 자연 모델을 썼다는 사실만으로 장면의 미감이 확보되지는 않았습니다. 색·크기·실루엣이 다른 식물을 넓은 빈 땅에 흩어 놓았고, 가는 갈대 잎은 십자 막대처럼 보였습니다.

- 일반 좌클릭으로 폰을 여는 연결을 제거하고 `ManualActivationOnly`를 적용했습니다. 장착·P 키·폰 버튼만 사용합니다. 작업 중 도착한 폰 열기 요청은 화면을 덮지 않습니다.
- 폰에 **이어서 하기**와 **목표 위치로 이동**을 넣었습니다. 서버가 현재 작업 앞의 안전한 도착점을 선택하며, 이동으로 학습 단계나 정산 기록이 바뀌지 않습니다.
- 한 화면에는 짧은 제목과 지금 필요한 내용, 주요 행동 하나를 둡니다. 반복되던 설명·목표·참고 문단을 없애고 세부사항은 펼쳐 볼 수 있게 했습니다. 작업 중 HUD와 다른 근접 프롬프트를 숨깁니다.
- 연결·발송·고료 응대의 중간 단계를 유지합니다. 이미 보낸 DM을 다시 보내거나 동일한 답장을 반복하는 흐름을 줄였습니다.
- 청록색 침엽수와 주황색 나무, 넓게 흩어진 막대 갈대를 교체했습니다. 둥근 활엽수 수관을 겹쳐 숲을 만들고, 갈대는 낮은 잎과 씨이삭이 연결된 군락으로, 바위는 해안의 묶음으로 배치했습니다. 색을 녹색·금빛·모래색으로 정리하고 언덕 높이를 낮췄습니다.

[Roblox Tool 입력](https://create.roblox.com/docs/reference/engine/classes/Tool#ManualActivationOnly)과 [Terrain 잔디](https://create.roblox.com/docs/reference/engine/classes/Terrain#Decoration)의 공식 API를 확인했습니다. 추가로 살펴본 Quaternius 자료는 이번 배포물에 사용하지 않았습니다. 실제 사용한 자연 모델은 Kenney CC0입니다.

이 수정의 코드 동작과 배치 미리보기는 확인했지만, Roblox Studio 플레이 검증과 실제 기기의 미감·가독성 판단은 여전히 남아 있습니다.

## 이전 설계의 문제

이전 맵은 실제 업무를 배우는 과정과 로블록스 플레이 양쪽에서 설득력이 약했습니다. 부스 여섯 개와 활동 열여덟 개가 있다는 사실을 교육 품질의 근거로 삼을 수 없습니다.

| 문제 | 플레이어에게 생긴 일 | v6에서 바꾼 구조 |
|---|---|---|
| 업무 설명 전 순서 맞히기 | 처음 배우는 사람에게 모르는 내용을 시험함 | 매니저에게 캠페인 의뢰를 받고, 그 맥락 안에서 직접 작업 |
| 여섯 부스가 같은 기능을 반복 | 이동이 다음 안내창을 여는 절차에 그침 | NPC 탐색, 프로필 확인, 도구 사용, 발송과 회신 처리로 행동 구분 |
| 웹 교육 화면을 중심으로 설계 | 캐릭터와 월드가 배경 장식이 됨 | 기본 화면에는 현재 목표만 표시하고 가까이서 E·터치로 상호작용 |
| 임의 이미지와 저해상도 표현 | 자료의 의미와 브랜드 일관성 손상 | 원본 시리아이 로고·프로필 6장, 별도의 가상 크리에이터 콘텐츠 사용 |
| 산·태양까지 그려진 이미지 벽 | 시점에 따른 입체감과 탐색 경험 부재 | 실제 고저차 지형·모래 해안·붉은 구체·입체 구름 구성 |
| 얇은 수면과 빈 바닥 | 물에 들어가면 추락하거나 죽음 | 실제 Terrain Water, 연속 해저, 해저 아래 비치명적 복귀 |
| 어댑터 테스트를 경험 검증과 혼동 | 코드가 실행된다는 사실로 재미·가독성까지 확인했다고 오해 | 코드 검증, 웹 배치 확인, 실제 Roblox 플레이 검증을 분리해 기록 |

## 참고한 Roblox 맵

2026-10-25에 아래 공식 경험 페이지와 제작자가 등록한 썸네일을 확인했습니다. 이 작업 환경에서는 해당 게임을 직접 플레이하지 못했습니다. 참고 이미지는 조사용 로컬 폴더에만 두며 배포물에 넣지 않았습니다.

- [Work at a Pizza Place / Dued1](https://www.roblox.com/games/192800/Work-at-a-Pizza-Place): 주문을 맡아 수행하는 역할놀이를 참고했습니다. 이번 맵의 단위도 퀴즈 한 문제가 아니라 캠페인 의뢰 한 건입니다.
- [Bee Swarm Simulator / Onett](https://www.roblox.com/games/1537690962/Bee-Swarm-Simulator): NPC에게 의뢰를 받고 행동으로 수행한 뒤 진행 결과를 받는 구조를 참고했습니다.
- [Fisch / Fisching](https://www.roblox.com/games/16732694052/Fisch): 도구를 들고 탐색하는 섬의 구성과 자연 속 휴식 방향을 참고했습니다. 특정 섬 지형·캐릭터·모델·음악은 가져오지 않았습니다.
- [Roblox: Onboarding](https://create.roblox.com/docs/production/game-design/onboarding): 첫 플레이에서 무엇을 왜 해야 하는지 이해시키고, 핵심 행동으로 빨리 진입시키는 기준을 적용했습니다.
- [Roblox: Core loops](https://create.roblox.com/docs/production/game-design/core-loops): 순간적인 행동, 반복하는 일, 진행 결과가 연결되는지 점검했습니다.

## 최초 v6의 플레이 단위 (v6.2 이전 기록)

시작 부두에서 매니저가 보입니다. 가까이 가서 E·터치로 캠페인을 받으면 도구창에 리크루터 폰이 생깁니다. 화면에는 현재 목표와 해당 대상의 표식만 표시됩니다.

프로필 PC에서 제공된 자료를 적용하고 연결 PC에서 수집 도구의 설정을 익힙니다. 크리에이터 정원에서는 NPC를 직접 만나 콘텐츠·팔로워·접촉 이력을 살펴보고 기준에 맞는 인원을 저장합니다. 잘못된 사람을 보는 것 자체는 오답 처리가 아닙니다. 해당 계정이 이번 모집 기준과 맞지 않는 이유를 확인하고 다른 사람을 탐색할 수 있습니다.

DM 우체통에서 전달받은 구간별 문구로 제안하고 시트 상태를 바꿉니다. 봉투가 대상에게 이동하며 작업 결과를 보여줍니다. 같은 계정에서 온 고료 조정 요청을 기록·공유하고, 모르는 제작 조건은 매니저에게 확인합니다. 이후 도착한 브랜드의 최종 선정 안내를 확인한 뒤 이번 기록을 마무리합니다.

긴 대시보드, 세 카드 순서 맞히기, 상대방을 모르는 상태에서 문구부터 고르는 퀴즈는 사용하지 않습니다. 실제 화면 입력이 필요한 프로필·연결·DM 작업에서는 작은 작업 창을 사용합니다.

## 유지한 실제 업무 기준

- 대상 선별 및 유효 DM 발송 1건 300원, 최종 선정 1명 2,000원.
- 기본 DM에 고료가 포함됩니다. 조정 요청에 대해 희망 금액을 기록하고 공유합니다.
- 제작 조건은 확인된 내용으로 회신합니다. 지원 완료와 최종 선정은 구분합니다.
- 연습 사례의 조건과 고료 구간을 모든 실제 캠페인의 공통 규칙으로 표현하지 않습니다.

## 확인 결과와 남은 한계

실제 Rojo 내보내기 결과의 클라이언트·서버 소스를 어댑터에서 실행해 전체 캠페인의 입력·상태 전환·근접 상호작용·요청 검증을 확인했습니다. 지형의 높이·수심·안전 복귀와 실제 지형 API의 정상·호환·실패 경로도 검사했습니다. 웹에서 동일한 지형과 모델 배치를 렌더링해 주요 시점과 모바일 페이지를 확인했습니다.

이 환경에는 Roblox Studio가 설치되어 있지 않습니다. 실제 엔진의 캐릭터 움직임, NPC 관절, 수영과 충돌, 글자 배치, 터치 조작, 여러 명이 접속한 상태의 사용성은 검증하지 못했습니다. 그러므로 이 파일은 **재설계한 v6 검토용 빌드**이며, 제작자가 인기 맵을 직접 플레이해 본 결과나 실제 플레이 검증을 마친 완성판이라고 표현하지 않습니다.
