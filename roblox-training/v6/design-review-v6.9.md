# v6.9 — 편집 화면의 바다·업무 사실관계: 수정 전 기준

기준일: 2026-10-26. 비교: v6.8 / 3ac1b5c.

## 확인된 원인과 범위
- 사용자는 물이 없는 화면을 **Studio 편집 화면**이라고 확인했다.
- v6.8 산출물의 Terrain에는 수면 데이터가 없고 MeadowWater 서버 스크립트가 Play 이후 생성한다. 따라서 편집 화면에 바다가 없는 것은 코드 구조로 재현된다. 런타임 물 고장으로 단정하지 않는다.
- 사용자 확인: 고료 조정 접수는 **캠페인별 지정 방식**을 따른다.
- 단톡의 실제 계정·전화번호·응답시트·메시지는 공개 파일에 복사하지 않는다. 교육에는 가상 계정과 일반화한 업무 절차를 쓴다.

## 통과 조건
| ID | 기준 | 확인 방법 |

| W1 | Studio가 파일을 열면 별도 실행 없이 수면이 존재 | 내보낸 맵에 해수면 높이의 수면 프리뷰가 바다 전체를 덮는지 검사 |
| W2 | Play에서는 실제 Terrain Water를 사용하고 프리뷰는 제거 | FillBlock의 Material.Water·수면 높이, 생성 성공/실패 콜백 검사 |

| F2 | 실제 팔로워·지정 탭/발송 대상·접촉 이력 확인·완료 공유를 기본 흐름에 포함 | 실제 UI 콜백의 기록 및 7개 챕터 완주 |
| F3 | 희망 고료는 지정 방식으로 접수·비고 기록, 별도 승인된 조정 범위는 그 안내 적용 | 고료 NPC/부록의 성공·오답 설명 대조 |

| F5 | 최근 접촉 제외·영상/광고 경험·캠페인 적합도 등 실제 선별 기준 반영 | 30초 벽면 선별 문제. 고료/소통은 무제한 유지 |

참고: Roblox 공식 Terrain 문서 https://create.roblox.com/docs/reference/engine/classes/Terrain . 편집 프리뷰는 수영 물리가 있는 Terrain 자체가 아니다. 실제 엔진 플레이는 Studio가 없는 이 환경에서 검증할 수 없으며, 웹 렌더와 콜백 검사를 별도로 표시한다.


## 검수 결과 — 2026-10-26

- W1: 실제 Rojo 내보내기 파일에서 수면 20개와 높이 -2를 확인. 모델의 2400×2800 범위에 빈틈이 없으며, 편집용 형상만 표시하는 별도 웹 대조에서도 수면을 확인했다.
- W2/W3: 물 서버 136개 검사 통과. 정상·호환 API·생성 실패 모두 검사했고, 생성 완료 후 수면 프리뷰를 숨긴다. 수면 프리뷰의 충돌·터치·질의는 모두 false다. 해안/수심/복귀 25,807개 검사와 연속 해저 검사 통과.
- F1–F5: 업무 대조표에 따라 기본 안내·가상 계정·DM·정산과 선택 심화/부록을 수정했다. 새 8개 심화 변형의 모든 선택지에 대해 254개 정답/오답·재시도·시간·보수 분리 검사 통과. 기본 7챕터 완주와 지원/최종 선정 기록 구분 검사도 통과.
- U1: 기존 폰의 큰 챕터·완료 표시와 설정 채우기 유지. 모바일 390×844에서 크리에이터 확인, 발송 기록, 고료 부록을 확인했다. 발송 기록의 긴 한 줄은 두 카드로 정리했다. 데스크톱 속성 렌더와 고료 NPC 방 웹 배치도 확인했다. 기본 과정에 추가 필수 퀴즈는 없다.
- 회귀: 원본 로고/이미지, 133스터드의 세 장소 동선, 입수 계단, 따봉 성장과 왕따봉 해금, 챕터 이동/재학습/폰 입력 검사 통과.
- 한계: 위 렌더는 저장된 Roblox 속성과 형상을 웹에서 대조한 결과다. Studio가 설치되지 않아 실제 편집 화면 렌더·수영 물리·엔진 UI 배치는 미검증이다. 편집 수면은 프리뷰이며 Play에서 만들어지는 Terrain Water와 구분한다.
