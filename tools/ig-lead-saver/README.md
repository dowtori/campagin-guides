> **1.5.0 검증 후보 · 2026-10-23**
>
> 실제 Chrome에서 기존 1.4의 HTTP 429 반복과 팔로워 배지 누락을 확인해 조회 구조를 변경했습니다.
> 1.5 소스의 자동 테스트와 Chrome 통제 화면 검증은 통과했습니다. **로그인한 실계정에 개선판을 설치한 뒤의 API 응답·실제 시트 저장·장시간 사용은 아직 검증하지 않았습니다.**
> 상세 근거는 [RESEARCH.md](RESEARCH.md), 검증 범위는 [VERIFICATION.md](VERIFICATION.md)를 확인하세요.

## 1.5 변경점

- 화면에 이미 보이는 팔로워 수와 페이지가 원래 수신한 공개 프로필 응답을 우선 재사용합니다.
- 같은 계정·같은 요청을 합치고, 24시간 캐시가 유효하면 추가 조회를 생략합니다.
- 추가 조회는 하나의 큐로 순차 처리합니다. 429·로그인 확인 응답을 받으면 다른 경로로 계속 재시도하지 않고 멈춥니다.
- 기존 접촉·이번 캠페인 저장 표시는 로컬 시트 이력에서 먼저 그립니다. 캠페인 전환과 이력 갱신을 분리합니다.
- 캠페인 변경 중 시작한 저장은 시작 시점의 캠페인에 기록하며, 늦게 도착한 이력 응답이 방금 저장한 계정을 지우지 않게 했습니다.
- Apps Script의 조회 요청은 저장 잠금 뒤에서 기다리거나 시트 헤더를 수정하지 않습니다.
- 긴 조회 제한 안내가 화면을 가리던 패널 폭을 260px로 제한했습니다.

### 기존 사용자의 적용 순서

1. 기존 확장 설정의 웹앱 URL·저장자·캠페인을 확인합니다.
2. 기존 버전이 압축 해제로 설치됐다면 새 파일을 해당 폴더에 적용하고 `chrome://extensions`에서 새로고침합니다. 웹스토어 설치 버전이라면 해당 버전을 잠시 끄고, 검증용 ZIP을 압축 해제한 폴더를 개발자 모드의 `압축해제된 확장 프로그램을 로드합니다`로 로드합니다. 새 확장에는 1번에서 확인한 설정을 입력합니다. 웹스토어 업데이트는 별도이며 이번 작업에서 배포하지 않았습니다.
3. 인스타그램 작업 탭을 새로고침합니다. 같은 작업 화면에 두 버전이 함께 실행되지 않게 합니다.
4. 실제 API 조회·시트 저장 검증을 마친 뒤 팀원에게 배포합니다.
5. 백엔드 개선도 적용하려면 `apps-script/Code.gs`를 기존 Apps Script에 반영하고 **기존 배포를 새 버전으로 수정**합니다. URL은 유지합니다. 기존 1.2 백엔드와도 저장·조회 메시지 형식은 호환되지만 조회 잠금 개선은 백엔드 업데이트 후에만 적용됩니다.

### 한계

인스타그램의 조회 제한을 해제하는 프로그램은 아닙니다. 캐시·화면·정상 응답에 없는 계정은 추가 조회가 필요합니다. 작성자까지 확인되지 않은 게시물은 프로필/게시물을 열어 확인해야 합니다. 팔로워 미확인 상태로 저장하면 유입경로에 표시하고, `1.2만`처럼 화면의 축약값을 읽은 경우에는 반올림값임을 표시합니다. 화면에서 숫자만 확보했을 때 소개·이메일 등 부가 항목은 빈 값일 수 있습니다.

### 자동 테스트

Node.js 20 이상에서 아래 명령을 실행합니다. 외부 계정·실제 시트를 사용하지 않습니다.

```sh
node --test tests/*.test.cjs
```

# IG Lead Saver — 인스타 인플루언서 시트 적립기

인스타그램을 돌아다니다 괜찮은 인플루언서를 발견하면 **버튼 하나로 구글시트에 적립**하는 크롬 확장.
DM은 천천히 보내더라도, 후보군은 미리 쌓아두기 위한 도구입니다.

## 저장되는 항목

| 저장일시 | 저장자 | 사용자명 | 프로필명 | 프로필 링크 | 팔로워 | 팔로잉 | 게시물 | 카테고리 | 이메일 | 연락처 | 외부 링크 | 소개 | 속성 | 유입경로 | 상태 | 태그 | 메모 | 프로필 사진 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

- **이메일 / 연락처**: 비즈니스 계정이 공개한 값이 있으면 자동으로 들어옵니다. DM 말고 메일로 접근할 수 있는 후보를 바로 걸러낼 수 있습니다.
- **속성**: 인증 / 비공개 / 비즈니스
- **상태**: `연락전 · DM 발송 · 회신 옴 · 협업 진행 · 보류 · 부적합` 드롭다운. DM 발송 페이스 관리를 이 컬럼으로 합니다.
- **유입경로**: 프로필 페이지 / 피드 게시물 / 목록·다이얼로그 / 단축키 / 우클릭 — 어디서 발굴했는지 남습니다.

## 저장 버튼이 뜨는 곳

1. **그리드 썸네일** — **태그됨 · 릴스 탭 · 탐색**에서 **프로필에 들어가지 않고** 바로 저장
2. **릴스 피드** — 릴스를 넘겨보다 마음에 들면 그 자리에서 저장
3. **프로필 페이지** — 좌측 하단 플로팅 독
4. **피드 · 게시물 헤더** — 작성자 옆 작은 `저장` 버튼
5. **팔로워 / 팔로잉 / 추천 목록** — 각 행 우측 미니 버튼
6. **단축키** `Alt` + `S`
7. **우클릭** — 프로필 링크 위에서 "이 프로필을 시트에 저장"

## 팀 운영 (v1.2)

### 저장자

시트의 **저장자** 열에 누가 넣었는지 남습니다. 로그인은 없고 이름만 적습니다.
설정 화면에서도, 인스타 화면의 플로팅 독에서도 바꿀 수 있습니다. 팀원마다 각자 자기 이름을 넣으면 됩니다.

### 캠페인 = 시트 탭

캠페인 하나가 시트 탭 하나입니다. 독의 `📁` 칩이나 설정 화면에서

- 시트에 **이미 있는 탭을 불러와 선택**하거나
- **새 탭을 그 자리에서 생성**할 수 있습니다 (헤더·드롭다운까지 자동 구성)

플로팅 독에 **지금 내 이름과 진행 중인 캠페인이 항상 떠 있습니다.** 접어놔도 헤더에 남습니다.
재접속했을 때 "내가 어느 캠페인에 담고 있었지"를 기억할 필요가 없게 하려는 것입니다.

### 중복 모집 방지

`_이력색인` 탭이 자동으로 유지됩니다. 계정명·최초저장일·저장자·캠페인·출처 5개 열만 담은 가벼운 색인입니다.

버튼 상태가 세 가지로 갈립니다.

| 표시 | 뜻 |
|---|---|
| `+ 시트에 저장` | 처음 보는 계정 |
| `✓ 저장됨` | **이번 캠페인**에 이미 담음 |
| `! 기존 접촉` | **과거 캠페인에서 이미 접촉** — 눌러서 저장할 수는 있지만 한 번 더 생각하라는 신호 |

전체 데이터를 한 탭에 밀어넣거나, 저장할 때마다 모든 탭을 훑는 방식은 쓰지 않았습니다.
전자는 캠페인 데이터와 이력이 섞이고, 후자는 7명이 동시에 쓸 때 Apps Script 실행 한도에 걸립니다.
색인은 **한 열만 읽으면 되므로** 사람이 늘어도 느려지지 않습니다.

과거 캠페인 이력은 `_이력색인` 탭에 `출처=과거캠페인`으로 미리 넣어두면 됩니다.

### 태그됨 탭에서 훑기 (주 사용 동선)

브랜드 계정 → **태그됨** 탭으로 들어가면, 협업했던 인플루언서들의 콘텐츠가 그리드로 쌓여 있습니다.

- 썸네일 좌상단에 **팔로워 수가 항상 큼직하게** 표시되고, 규모 구간에 따라 색이 달라집니다.

  | 구간 | 표시 |
  |---|---|
  | ~1천 | 흐린 회색 칩 — 관심 범위 밖이라 물러나 있음 |
  | 1천~1만 | 연한 골드 |
  | 1만~5만 | 앰버 |
  | 5만~100만 | 진한 오렌지 |
  | 100만~ | 블랙 + 골드 + **★ 별** |

  크기 순서를 나타내는 값이라 브랜드 블룸(골드→오렌지)을 순차 램프로 씁니다.
  마젠타는 `기존 접촉` 경고가 쓰고 있어 의미 충돌을 피해 제외했습니다.

  양 끝이 모두 어두워 헷갈리지 않도록, 최하위는 **글자와 아이콘까지 흐리게 죽이고**
  최상위는 **별 아이콘**을 더했습니다. 색이 아니라 모양으로 갈리므로 나란히 놓여도 즉시 구분됩니다.
  전 구간 명도 대비 AA를 통과합니다 (사진 위 알파 합성 기준 최저 4.88:1).

- 마우스를 올리면 하단에 `@계정명 ✔ · 팔로워 12.3만` 이 함께 뜹니다.
- 그대로 **저장** 버튼을 누르면 시트에 적립됩니다. 페이지 이동이 전혀 없습니다.
- 이미 저장한 계정의 타일은 **호버 없이도** 항상 `저장됨 ✓` 이 떠 있어, 그리드를 훑는 중에 중복을 즉시 걸러낼 수 있습니다.
- 마우스를 올리기 전에 저장 버튼을 바로 눌러도 됩니다. 그 순간 작성자를 찾아 저장합니다.

> **원리** — 태그됨 탭의 썸네일 링크는 `/{계정명}/reel/{코드}/` 형식이라 **작성자가 URL에 이미 들어 있습니다.** 따라서 조회 없이 즉시 계정명을 표시합니다. 팔로워 수만 호버 시 한 번 가져오고, 결과는 캐시되어 저장할 때 재요청하지 않습니다.
>
> 링크가 `/p/{코드}/` 형식이라 작성자를 알 수 없는 경우(탐색 탭 등)에는, shortcode가 게시물 ID를 base64로 인코딩한 값이라는 점을 이용해 역산 후 작성자를 조회합니다.

이미 시트에 있는 계정은 버튼이 **저장됨 ✓**으로 표시되어, 같은 사람에게 두 번 접근하는 일을 막아줍니다.

## 설치 (5분)

### 1단계 — 구글시트 준비

1. 새 구글시트를 만듭니다.
2. 메뉴 **확장 프로그램 → Apps Script**.
3. `apps-script/Code.gs` 내용을 전부 복사해 붙여넣고 저장합니다.
4. 우측 상단 **배포 → 새 배포 → 유형 선택(톱니) → 웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자** ← 이게 아니면 확장이 로그인 페이지를 받아 실패합니다
5. **배포**를 누르고 권한을 승인한 뒤, 나오는 `.../exec` 로 끝나는 URL을 복사합니다.

> 미확인 앱 경고가 뜨면 `고급 → (프로젝트명)(으)로 이동`. 본인이 작성한 스크립트라 정상입니다.

### 2단계 — 확장 프로그램 설치

1. 크롬에서 `chrome://extensions` 접속
2. 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** → 이 `ig-lead-saver` 폴더 선택

### 3단계 — 연결

1. 확장 아이콘 → **설정 열기** (또는 확장 관리에서 옵션)
2. 1단계에서 복사한 웹앱 URL 붙여넣기
3. **연결 테스트** → `연결됨 · (시트이름)` 이 나오면 완료

인스타그램 탭이 이미 열려 있었다면 새로고침 한 번 해주세요.

## 동작 방식

```
content.js  ──(인스타 내부 API로 프로필 상세 조회)──▶ instagram.com
     │
     │ chrome.runtime.sendMessage
     ▼
background.js ──(POST, JSON)──▶ Apps Script 웹앱 ──▶ 구글시트
```

- 프로필 정보는 인스타그램 웹이 자기 화면을 그릴 때 쓰는 내부 엔드포인트(`web_profile_info`)에서 가져옵니다. 로그인한 본인 세션으로 조회하므로 별도 인증이 없습니다.
- 시트 통신은 백그라운드 워커가 담당합니다. 콘텐츠 스크립트에서 직접 쏘면 CORS에 막힙니다.
- 중복은 **시트의 사용자명 컬럼 기준**으로 판정합니다. 시트에서 행을 지우면 다시 저장할 수 있습니다.

## 자주 겪는 문제

| 증상 | 원인 / 해결 |
|---|---|
| `웹앱이 JSON 대신 로그인 페이지를 반환` | Apps Script 배포의 액세스 권한이 "모든 사용자"가 아님. 배포 관리 → 편집 → 다시 설정 |
| 버튼이 안 보임 | 인스타 탭 새로고침. 그래도 없으면 `chrome://extensions`에서 확장 새로고침 후 재시도 |
| 팔로워 수가 비어 있음 | 인스타 내부 API가 일시적으로 막힌 경우. 링크·사용자명은 저장되므로 시트에서 나중에 보완 가능 |
| 썸네일에 `작성자 조회 실패` | 비공개 계정이거나 삭제된 게시물입니다. 다른 타일은 정상 동작합니다 |
| 썸네일 버튼이 거슬림 | 설정 → **버튼 노출 위치**에서 "그리드 썸네일" 또는 하위의 "마우스를 올리면 미리 표시"만 끌 수 있습니다 |
| 저장됨 표시가 초기화됨 | 옵션의 **시트에서 저장목록 불러오기**를 누르면 시트 기준으로 다시 맞춰집니다 |
| Code.gs를 수정했는데 반영이 안 됨 | **새 배포**가 아니라 *배포 관리 → 편집(연필) → 버전: 새 버전*으로 갱신해야 URL이 유지됩니다 |

## 사용 시 유의

인스타그램은 자동화된 대량 수집을 약관으로 제한합니다. 이 확장은 **사람이 직접 클릭한 프로필만** 한 건씩 조회·저장하며, 자동 스크롤이나 일괄 수집은 하지 않습니다. 짧은 시간에 수백 건을 연타하면 계정에 일시 제한이 걸릴 수 있으니, 평소 브라우징 속도로 사용하세요.

   └─ Code.gs         구글시트 백엔드

## 디자인 기준

siriai.co.kr의 시각 언어를 따릅니다.

| 요소 | 값 |
|---|---|
| 타이포 (라틴) | **Inter Tight** 가변 폰트 — 확장에 번들, 네트워크 의존 없음 |
| 타이포 (한글) | 시스템 폰트 폴백 (Pretendard → Apple SD Gothic Neo → 맑은 고딕) |
| 자간 | 본문 `-0.011em`, 헤딩 `-0.032em` — 사이트의 타이트한 트래킹 |
| 배경 | `#0a0a0a` near-black |
| 강조 | 웜 앰버 `#e0a25e → #c67e3a` |
| 아이콘 | SIRIAI 원형 S 모노그램 + 우하단 앰버 글로우 |

한글 웹폰트(Noto Sans KR 등)는 수백 KB라 번들하지 않았습니다. 인스타에 주입되는 CSS도 웹폰트 없이 시스템 헬베티카/Arial을 씁니다 — 주입 자원을 최소화하기 위해서입니다.

인스타 버튼을 앰버로 잡은 건 브랜드 일치 목적도 있지만, 인스타 자체 UI(파랑·핑크 그라디언트)와 색이 겹치지 않아 **어느 게 우리 버튼인지 한눈에 구분**되기 때문입니다.
