## Chrome 통제 화면에서 확인한 결과

- 실제 화면에서 확인한 `href="#"`, `팔로워` 라벨, title 숫자 구조를 재현했습니다.
- 표시된 팔로워 3,744명을 6개 타일에 반영했고, Instagram 추가 요청은 **0회**였습니다.
- 저장 버튼 클릭 후 동일 계정의 6개 타일이 모두 `저장됨`으로 바뀌었습니다. 저장 데이터의 팔로워 값은 3,744였습니다. 시트 응답은 모의 응답입니다.
- 태그된 게시물 시나리오에서 정상 페이지 JSON의 작성자·팔로워를 재사용해 1.2만/7천 배지가 표시됐습니다.
- `prior`는 기존 접촉, `selected`는 이번 캠페인 저장, 신규 계정은 저장 버튼으로 구분했습니다.
- 가짜 429 응답 이후 대기 시간 동안 추가 조회 없이 기존 이력/배지를 유지했습니다. 대기 만료 후에는 다음 조회를 허용합니다. 이를 Instagram 제한이 해제되었다는 뜻으로 표시하지 않습니다.
- 팔로워 조회가 실패한 계정을 저장하면 빈 숫자와 `팔로워 미확인` 표시가 전송되고 완료 안내에도 동일하게 나타났습니다.
- 이 수치는 **요청 생략·상태 전환에 관한 통제된 결과**입니다. 실제 인스타그램 전후 속도 측정값은 없습니다.

## 실행 중 발견해 고친 불편

1. 최신 화면은 팔로워 링크가 `#`여서 초기 개선안의 `/followers/` 선택자가 숫자를 놓쳤습니다. 화면 라벨과 정확한 title 숫자도 읽도록 수정하고 테스트를 추가했습니다.
2. 조회 제한 안내가 길어지면서 독이 약 500px까지 늘어나 게시물을 가렸습니다. 260px로 제한하고 줄바꿈을 적용한 후 Chrome에서 실측 260px와 화면을 확인했습니다.
3. 로그인 후 재확인 시 계정별 실패 캐시가 남아 즉시 재시도하지 못할 수 있었습니다. 재확인 때 실패 캐시도 해제하도록 수정했습니다.
4. 대기 중 다른 탭이 제한을 받는 경우를 고려해 요청 간격을 기다린 뒤에도 공유 제한 상태를 다시 확인합니다.
5. 조회 대기 중이던 타일이 대기 종료 후 복구 대상에서 빠질 수 있어 복구 큐 등록·재개를 보완했습니다. 실제 Instagram에서의 장시간 복구는 미검증입니다.

## 자동 테스트 내용

- profile-core 15개: 공개 필드 선별, 게시물 직접 작성자, 축약값 표기, 최신 화면 라벨, 0 요청, 0명 처리, TTL, 중복 합치기, pk 조회, 잘못된 작성자 방지, 429/401/400/500, 응답 시간 초과, 다른 탭의 대기 상태.
- background 7개: 설정 응답과 이력 통신 분리, 동시 갱신 합치기, 캠페인 전환, 저장 시작 시점 캠페인 유지, 늦은 응답과 새 저장 충돌, endpoint 분리, 잘못된 응답 보존.
- Apps Script 5개: 조회 3종의 잠금 미사용, 저장 후 flush/잠금 해제, 실패 시 잠금 해제.
- observer 1개: 자체 추가 요청 없이 원래 fetch 결과를 보존하고 공개 항목만 전달.

실행: `node --test tests/*.test.cjs`

## 완료 판정을 위한 남은 절차

현재 브라우저 연결 도구는 `chrome://extensions` 내부 페이지를 제어하지 못합니다. 개선판을 기존 확장 폴더에 적용하고 확장을 새로고침하는 단계가 필요합니다. 그 뒤 로그인한 작업 탭에서 팔로워 수 비교, 새로 연 계정 조회, 실제 시트 저장/중복/캠페인 전환, 장시간 사용을 확인해야 합니다. 그 전에는 팀 전체 배포용 확정판으로 안내하지 않습니다.
